# Two Cents v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reimplement Two Cents (currently Django + HTMX) as a TypeScript pnpm monorepo with Fastify backend + Vite/React SPA, deployed alongside Dinner Club's pattern on S2. Strict feature parity with v1 (including multi-item bundles, push notifications, scheduled tasks, appeals, feedback, settings, household management, PWA).

**Architecture:** Two-app monorepo. Fastify API speaks JSON; React SPA fetches. Both served behind one nginx host (`/api/*` → API, everything else → web container) so cookies are same-origin. State machine, delays, all-mode resolution ported as pure TS modules with Vitest coverage. BullMQ for background jobs. Authentik OIDC via `openid-client` + `iron-session`. Prisma against a fresh `two_cents_v2` Postgres database; cutover is truncate-and-restart (3 users + 2 requests is trivial to recreate).

**Tech Stack:**
- pnpm workspace · TypeScript 5 strict
- Fastify 5 · Prisma 5 · BullMQ · openid-client · iron-session · web-push · @aws-sdk/client-s3 · Zod · Pino
- Vite 6 · React 18 · react-hook-form + @hookform/resolvers · TanStack Query · Tailwind 3 · shadcn/ui · radix-ui primitives
- Vitest · Playwright · ESLint · Prettier
- Docker · Caddy (web) · Postgres (shared-infra) · Redis (shared-redis) · MinIO (existing) · Authentik (existing) · Vault (existing) · LC2 nginx + Cloudflare Tunnel

**Companion docs:**
- Product spec: [`docs/purchase-request-app-spec.md`](../../purchase-request-app-spec.md) (carried over from v1)
- v1 design: [`docs/superpowers/specs/2026-04-28-two-cents-design.md`](../specs/2026-04-28-two-cents-design.md)

**Reference:** Dinner Club is the same stack on the same host (`/opt/dinner-club/`). Mirror its conventions for compose, nginx, runner, secrets, networks.

## Operating notes

- **Working dir:** `d:/code/two-cents-v2/` (Windows, bash). HEAD starts at empty — Phase 0 makes the first commit.
- **uv / Python:** not used here. This is Node-only.
- **Node:** 22 LTS. Use `pnpm` (not npm/yarn).
- **Git:** Do NOT push during phase work; commit locally only. Pushes happen at phase boundaries via `gh auth token`-based HTTPS push (see commit messages — use `git -c commit.gpgsign=false`).
- **Postgres dev:** spin up an ephemeral container per test session: `docker run --rm -d --name pg-tc -p 5433:5432 -e POSTGRES_USER=two_cents_v2 -e POSTGRES_PASSWORD=two_cents_v2 -e POSTGRES_DB=two_cents_v2 postgres:16`. Use `DATABASE_URL=postgresql://two_cents_v2:two_cents_v2@localhost:5433/two_cents_v2`.
- **Redis dev:** `docker run --rm -d --name redis-tc -p 6379:6379 redis:7`. Use `REDIS_URL=redis://localhost:6379/0`.
- **Reference repo:** v1 lives at `d:/code/two-cents/`. Read freely from `apps/requests_app/state.py`, `apps/requests_app/delays.py`, `apps/requests_app/services.py`, `apps/requests_app/resolution.py`, `apps/notifications/jwt.py`, `apps/notifications/services.py`, `apps/notifications/events.py`, `apps/appeals/services.py` for the canonical logic to port.

```prisma
// schema.prisma — Two Cents v2
generator client {
  provider = "prisma-client-js"
  output   = "../node_modules/.prisma/client"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

// --- accounts ---

model User {
  id           Int      @id @default(autoincrement())
  oidcSubject  String   @unique @map("oidc_subject")
  name         String   @default("")
  isAdmin      Boolean  @default(false) @map("is_admin")
  createdAt    DateTime @default(now()) @map("created_at")

  memberships         HouseholdMember[]
  comments            Comment[]
  pushSubscriptions   PushSubscription[]
  notificationPrefs   NotificationPreference[]
  notificationLogs    NotificationLog[]
  feedbackSubmissions FeedbackSubmission[]

  @@map("users")
}

// --- households ---

enum ApprovalMode {
  any
  all
}

enum AppealPeriod {
  monthly
  quarterly
}

model Household {
  id                 Int          @id @default(autoincrement())
  name               String
  appealQuotaCount   Int          @default(2) @map("appeal_quota_count")
  appealQuotaPeriod  AppealPeriod @default(quarterly) @map("appeal_quota_period")
  createdAt          DateTime     @default(now()) @map("created_at")

  members  HouseholdMember[]
  pending  PendingMembership[]
  requests Request[]

  @@map("households")
}

model HouseholdMember {
  id            Int          @id @default(autoincrement())
  householdId   Int          @map("household_id")
  userId        Int          @map("user_id")
  approvalMode  ApprovalMode @default(any) @map("approval_mode")
  joinedAt      DateTime     @default(now()) @map("joined_at")

  household     Household @relation(fields: [householdId], references: [id], onDelete: Cascade)
  user          User      @relation(fields: [userId], references: [id], onDelete: Cascade)

  approverLinks BuyerApprover[] @relation("BuyerApprover_buyer")
  buyerLinks    BuyerApprover[] @relation("BuyerApprover_approver")
  requests      Request[]
  reviews       Review[]
  appeals       Appeal[]

  @@unique([householdId, userId])
  @@map("household_members")
}

model BuyerApprover {
  id         Int @id @default(autoincrement())
  buyerId    Int @map("buyer_id")
  approverId Int @map("approver_id")

  buyer    HouseholdMember @relation("BuyerApprover_buyer", fields: [buyerId], references: [id], onDelete: Cascade)
  approver HouseholdMember @relation("BuyerApprover_approver", fields: [approverId], references: [id], onDelete: Cascade)

  @@unique([buyerId, approverId])
  @@map("buyer_approvers")
}

model PendingMembership {
  id                 Int          @id @default(autoincrement())
  householdId        Int          @map("household_id")
  authentikUsername  String       @map("authentik_username")
  approvalMode       ApprovalMode @default(any) @map("approval_mode")
  createdAt          DateTime     @default(now()) @map("created_at")

  household Household @relation(fields: [householdId], references: [id], onDelete: Cascade)

  @@unique([householdId, authentikUsername])
  @@map("pending_memberships")
}

// --- requests ---

enum RequestStatus {
  pending
  approved
  delayed
  awaiting_reconfirm
  denied
  cancelled
  archived
  purchased
}

enum Seriousness {
  need
  really_want
  nice_to_have
}

enum ReviewAction {
  approve
  delay
  deny
```

# Phase 16 — Restore Claude Code permissions

End of phase: Claude Code is back to safe-by-default permission prompts. The temporary bypass mode (enabled mid-rewrite to keep dispatched agents from stalling on confirmation dialogs) is removed, and the auto-accumulated `allow` list is trimmed to a small set of long-lived patterns useful for future maintenance.

This phase is intentionally last: it shouldn't run until Phase 15 cutover has shipped and the rewrite is done. Before then, the bypass mode is doing useful work.

## Task 16.1: Revert `bypassPermissions` mode

Edit `.claude/settings.local.json` in the worktree (and the main checkout's `.claude/settings.local.json` if it has one) and remove the `defaultMode` line:

```diff
 {
   "permissions": {
-    "defaultMode": "bypassPermissions",
     "allow": [...]
   }
 }
```

Or change it explicitly to `"default"`. Either works; removing is cleaner.

After saving, the next session reverts to the normal flow: Claude prompts before destructive actions, accepts edits without prompting (per Claude Code defaults).

## Task 16.2: Curate the `allow` array

`.claude/settings.local.json` will likely contain hundreds of `Bash(...)` entries auto-accumulated from per-action approvals over the project's lifetime. Most are session-specific (absolute paths in commit messages, one-off debug commands, hash-specific git commands) and useless going forward.

Trim to a small set of patterns that will keep being useful for ongoing maintenance:

```json
{
  "permissions": {
    "allow": [
      "Bash(git -C * status)",
      "Bash(git -C * log:*)",
      "Bash(git -C * show:*)",
      "Bash(git -C * diff:*)",
      "Bash(git fetch:*)",
      "Bash(COREPACK_INTEGRITY_KEYS=0 pnpm:*)",
      "Bash(docker ps:*)",
      "Bash(docker logs:*)",
      "Bash(docker exec * pg_isready:*)",
      "Bash(docker exec * redis-cli ping)",
      "Bash(gh auth status)",
      "Bash(gh run list:*)",
      "Bash(gh run view:*)",
      "Bash(gh pr list:*)"
    ]
  }
}
```

Adjust patterns to whatever you actually find yourself approving repeatedly. The goal is "no friction on read-only inspection, prompt for everything destructive."

## Task 16.3: Spot-check that prompts come back

In a fresh Claude Code session in this project:
- Ask Claude to do a `git status` — should pass through without a prompt (covered by allow list)
- Ask Claude to do `rm` something — should prompt (no allow rule, no bypass mode)
- Ask Claude to write a new file — should prompt (the default mode does NOT auto-accept edits)

If the third item DOESN'T prompt, the bypass-mode setting wasn't fully removed. Re-check the file.

## Task 16.4: Commit + push (NOT applicable — settings.local.json is gitignored)

`.claude/settings.local.json` is local-only by design. No commit needed; the change applies the next time Claude Code reads the file. The `.claude/` directory is in `.gitignore` from Phase 0.

No git changes; no push. Phase 16 ends with a clean working tree and a clean Claude Code permission surface.
